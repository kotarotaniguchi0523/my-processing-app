# AIコーディングエージェント 要件定義書 (v2 Full)

## 1. プロジェクト概要

### 1.1 プロジェクト名

AI Processing Coding Agent - エージェント型描画支援AIチャットシステム

### 1.2 目的

自然言語による指示をAIエージェントが解釈し、定義済みの「ツール」を実行することでProcessingの描画指示（YAML）を生成、**ユーザーの承認を経て**リアルタイムで実行・表示する対話型システムを構築する。

### 1.3 ビジョン

ユーザーがAIエージェントと対話しながら、安全かつ主体的にビジュアル表現を段階的に構築できる環境を提供する。AIの提案を確認・承認するプロセスを通じて、Processingの構造的な理解を促進する教育的ツールを目指す。

### 1.4 スコープ

#### 含む:

- チャット形式のUI
- AIエージェント（思考ループ、ツール呼び出し）
- **描画内容の変更提案とユーザーによる承認ワークフロー**
- 描画のリアルタイム実行
- 状態の履歴管理（アンドゥ/リドゥ）
- セッションの保存/読み込み

#### 含まない:

- 3D描画、音声処理、外部ハードウェア連携
- リアルタイム・マルチユーザー対応

## 3. 機能要件

### 3.1 ユーザーインターフェース

#### 3.1.1 メインウィンドウ

- **サイズ**: 800x600ピクセル（デフォルト）、リサイズ可能
- **レイアウト**:
  - 上部50%: 描画エリア
  - 下部40%: チャット履歴
  - 下部10%: 入力欄

#### 3.1.2 描画エリア

- 白背景のキャンバス
- リアルタイム描画更新
- マウスインタラクション対応
- グリッド表示オプション（将来実装）

#### 3.1.3 チャットインターフェース

- **チャット履歴表示**:
  - 最大100メッセージ保持
  - スクロール機能
  - タイムスタンプ表示
  - ユーザー/AIの識別表示

- **入力欄**:
  - 日本語・英語入力対応
  - Enterキーで送信
  - 複数行対応（Shift+Enter）
  - 文字数制限: 500文字

#### 3.1.4 承認オーバーレイ

- **目的**: AIエージェントが提案した変更内容をユーザーに提示し、承認または拒否を求める。
- **表示タイミング**: チャット入力が無効化され、モーダルウィンドウまたは入力欄上部に表示される。
- **表示内容**:
  - 変更内容の要約（例: 「円を1つ追加し、四角の色を変更します」）
  - 変更差分（Diff）の表示
  - 「適用(Approve)」ボタン
  - 「破棄(Reject)」ボタン

### 3.2 AIエージェント機能

#### 3.2.1 対話と思考ループ

- ユーザーの単一の指示に対し、エージェントは内部的に複数のステップ（思考、ツール呼び出し）を繰り返すことがある。
- エージェントは、最終的な描画指示を生成するまで、または最大反復回数に達するまで思考ループを実行する。

#### 3.2.2 ツール呼び出し (Tool Calling)

- AIは直接YAMLを生成するのではなく、システムに事前定義された「ツール」を呼び出す形式で応答する。
- AIは、ユーザーの指示を達成するためにどのツールを、どのパラメータで呼び出すべきかを判断する。
- 承認が必要なツール呼び出しは、ユーザー承認ワークフローをトリガーする。

#### 3.2.3 サポートツール一覧

- **描画ツール**: `createShape`, `modifyShape`, `deleteShape`
- **配列操作ツール**: `createArray`, `modifyArray`
- **リスト操作ツール**: `createList`, `modifyList`
- **ユーティリティツール**: `clearCanvas`, `changeBackground`

### 3.3 ユーザー承認ワークフロー

#### 3.3.1 ワークフローのトリガー

以下の操作を含むツールが呼び出された場合、ワークフローが開始される。

- 新しい図形を複数（例: 3個以上）同時に追加する操作
- 既存の図形を複数同時に変更・削除する操作
- キャンバス全体をクリアする操作

#### 3.3.2 差分計算とプレビュー

- エージェントがツールの実行を提案した際、システムは現在の描画状態と提案後の状態との差分（Diff）を計算する。
- 差分は、承認オーバーレイ内でテキスト形式（追加、削除、変更）でユーザーに提示される。
- （将来実装）差分を適用した場合のプレビューを、元の描画に重ねて表示する。

#### 3.3.3 承認と実行

- ユーザーが「適用」を選択した場合、ツールの実行が確定し、生成されたYAMLが描画エンジンに渡され、キャンバスが更新される。
- ユーザーが「破棄」を選択した場合、提案はキャンセルされ、何も変更は行われない。エージェントには「ユーザーによって操作が拒否された」という情報がフィードバックされる。

### 3.4 描画実行機能

（注: 以下の描画はすべてAIエージェントによる「ツール」の実行結果として行われる）

#### 3.4.1 サポートする図形

| 図形 | パラメータ | 備考 |
|---|---|---|
| ellipse（円/楕円） | x, y, width, height, fill, stroke | |
| rectangle（四角） | x, y, width, height, fill, stroke | |
| triangle（三角） | x1, y1, x2, y2, x3, y3, fill, stroke | |
| line（線） | x1, y1, x2, y2, stroke, strokeWeight | |
| arc（円弧） | x, y, width, height, start, stop | |
| quad（四辺形） | x1, y1, x2, y2, x3, y3, x4, y4 | |
| point（点） | x, y, stroke | |

#### 3.4.2 配列操作

- `linear_array`: 直線配置（等間隔）
- `grid_array`: グリッド配置
- `circular_array`: 円形配置
- `random_array`: ランダム配置
- `spiral_array`: 螺旋配置

#### 3.4.3 動的操作（ArrayList）

- 要素の追加/削除
- シャッフル
- ソート（サイズ、位置）
- グループ化

### 3.5 状態管理機能

#### 3.5.1 履歴管理

- **保存内容**: YAML状態、実行されたツールコマンド、タイムスタンプ
- **最大履歴数**: 50状態
- **操作**: アンドゥ、リドゥ、特定状態へジャンプ
- **単位**: アンドゥ/リドゥは、**ユーザーが承認した操作**の単位で行われる。

#### 3.5.2 差分表示（Cline風）

- **差分計算**: 現在状態とAIが提案した新状態の比較
- **表示形式**:
  - 追加: `+ fill: "#FF0000"` ✅
  - 削除: `- fill: "#0000FF"` ❌
  - 変更: `~ x: 100 → 200`
- **選択的適用**: （将来実装）個別の変更を承認/拒否
- **プレビュー**: 変更前後の比較表示

#### 3.5.3 セッション管理

- 作業内容の自動保存（5分ごと）
- プロジェクトファイル（.yaml）としてエクスポート
- セッション復元機能

### 3.6 データ形式仕様

（注: このYAMLはAIの直接出力ではなく、各ツールの実行結果として生成される）

#### 3.6.1 YAML構造

```yaml
# メタ情報
metadata:
  version: "1.0"
  created: "2025-09-05T10:00:00"

# 設定
settings:
  clear: true/false
  background: "#FFFFFF"
  size: [800, 600]

# 単体図形
shapes:
  - id: "shape_001"
    type: "ellipse"
    x: 200
    y: 200
    width: 100
    height: 100
    fill: "#FF0000"
    stroke: "#000000"
    strokeWeight: 2

# 配列描画
arrays:
  - id: "array_001"
    type: "ellipse_array"
    count: 10
    start_x: 50
    start_y: 100
    spacing: 60
    properties:
      width: 50
      height: 50
      fill: "#0000FF"

# 動的リスト
lists:
  - id: "list_001"
    type: "random_circles"
    count: 20
    x_range: [0, 800]
    y_range: [0, 400]
    size_range: [10, 50]
    colors: ["#FF0000", "#00FF00", "#0000FF"]
```

### 3.7 API仕様

#### 3.7.1 Claude API / Gemini API 連携

- **認証**: APIキー（環境変数で管理）
- **プロンプト構造**:
  - **システムプロンプト**: AIエージェントとしての役割、思考プロセス、そして利用可能な**全ツールの一覧とそのJSONスキーマ定義**が含まれる。
  - **会話履歴**: ユーザーとアシスタント（ツール呼び出し/結果を含む）の対話履歴。
  - **ユーザー入力**: 最新のユーザーからの指示。
- **レスポンス形式**: AIはツールを呼び出すためのJSON、または最終的なテキスト応答を返す。

## 4. 非機能要件

### 4.1 パフォーマンス

- **描画更新**: 30 FPS以上
- **API応答時間**: 5秒以内
- **YAML解析**: 100ms以内
- **起動時間**: 3秒以内

### 4.2 信頼性

- **可用性**: 99%（ローカル実行時）
- **エラー復旧**: 自動リトライ（API通信）
- **データ保護**: 自動バックアップ

### 4.3 ユーザビリティ

- **学習時間**: 10分以内で基本操作習得
- **エラーメッセージ**: 日本語対応、具体的な解決策提示
- **ヘルプ機能**: コマンド一覧、使用例

### 4.4 セキュリティ

- **APIキー**: 環境変数または設定ファイル（`.gitignore`対象）
- **入力検証**: インジェクション攻撃等を防ぐためのサニタイズ
- **実行制限**: 危険なコード実行に繋がるツールの実装防止

### 4.5 拡張性

- **プラグイン構造**: 新しいツール（図形、操作）の追加が容易
- **API追加**: 他のAIサービス対応が可能
- **エクスポート**: Processing IDE用コード生成

## 5. 制約事項

### 5.1 技術的制約

- 動的コンパイル機能は実装しない（安全性の観点）
- 3Dグラフィックスは対象外
- 音声入出力は非対応
- リアルタイムコラボレーションは非対応

### 5.2 リソース制約

- APIコール数の制限（プロバイダーの制限に準拠）
- 最大描画オブジェクト数: 1000個
- メモリ使用量: 最大2GB

### 5.3 運用制約

- インターネット接続必須（AI機能使用時）
- シングルユーザーのみ対応

## 6. 実装フェーズ

- **Phase 1: 基本機能（MVP）**
  - 基本UI（描画、チャット）の実装
  - エージェントの基本骨格と思考ループの実装
  - 基本的な描画ツールの実装（AI連携なし）

- **Phase 2: AI連携とツール拡充**
  - AI API（Claude/Gemini）との統合
  - プロンプトにツールスキーマを組み込む機能
  - AIによるツール呼び出し機能の実装

- **Phase 3: 承認ワークフローと状態管理**
  - 差分計算・表示機能の実装
  - 承認オーバーレイUIの実装
  - ユーザー承認を待つ非同期ワークフローの実装
  - アンドゥ/リドゥ機能

- **Phase 4: 高度な機能**
  - アニメーション対応
  - プロジェクト保存/読み込み
  - コード生成・エクスポート
  - パフォーマンス最適化

## 7. テスト要件

### 7.1 単体テスト

- 各ツールの正常系/異常系の動作確認
- YAML解析の妥当性
- 差分計算ロジックの検証

### 7.2 統合テスト

- AI連携のエンドツーエンドシナリオ（指示→ツール呼び出し→YAML生成）
- ユーザー承認ワークフロー全体のシナリオテスト
- エラー復旧機能

### 7.3 ユーザビリティテスト

- 初心者による操作テスト
- API応答を含めた全体の応答時間の測定
- UI/UXの改善点抽出

## 8. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|---|---|---|---|
| API制限超過 | 高 | 中 | キャッシュ機能、使用状況のUI表示 |
| AIの不適切なツール呼び出し | 中 | 高 | ツール側のパラメータ検証、サンドボックス実行 |
| パフォーマンス低下 | 中 | 中 | 最適化、オブジェクト数制限、プロファイリング |
| AIの不適切な応答 | 低 | 中 | プロンプト改善、フィルタリング、ユーザーによる拒否 |

## 9. 成功指標

### 9.1 定量的指標

- **平均応答時間**: 5秒以内（ユーザー指示から描画反映まで）
- **成功率**: 90%以上の指示を正しく解釈し、適切なツールを呼び出す
- **安定性**: 1時間連続使用でクラッシュなし

### 9.2 定性的指標

- ユーザーがAIの提案を理解し、直感的に承認/拒否できる
- 生成される描画がユーザーの期待通りである
- 承認プロセスが学習ツールとして有効に機能する
